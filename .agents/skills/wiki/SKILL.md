# Project Wiki Skill (Karpathy LLM RAG)

이 프로젝트 스코프 스킬은 프로젝트 개발에 관한 전반적인 운영 지식 및 메타 가이드를 `wiki/` 디렉토리에 마크다운 형식으로 보관하고 관리합니다. 
동시에, 나중에 블로그 포스팅 작성을 진행할 때 참조하는 **콘텐츠용 기술 지식**은 `content/wiki/` 디렉토리 아래에 관리됩니다.

전역 설정된 `hooks.json`의 `PreInvocation` RAG 훅을 통해 `content/wiki/` 내의 마크다운 지식 내용이 질문 시 자동으로 로드되어 에이전트의 상황 지식(RAG)으로 제공됩니다.

## 위키 작성 및 관리 규칙

### A. 프로젝트 운영 위키 (`wiki/`)
- **역할**: 프로젝트 아키텍처, 빌드 가이드, Blogger API OAuth 설정, 에이전트 가이드라인 및 매 세션 종료 시의 자동 대화 요약기록(`Session_History.md`)을 보관합니다.
- **자동 요약 훅**: 에이전트 세션 종료(`Stop` 라이프사이클 이벤트) 시, 전역 훅(`stop_handler.js`)에 의해 이력 요약본이 `wiki/Session_History.md` 상단에 누적 갱신(Prepends)됩니다.

### B. 블로깅 콘텐츠 위키 (`content/wiki/`)
- **역할**: 나중에 에이전트들이 블로그 글을 새로 집필할 때 리서처와 작성자의 1차 상황 지식이 되는 기술적인 이론 문서를 축적합니다.
- **RAG 연동**: 질문 수신 시 훅 스크립트에 의해 이 폴더 내의 관련 키워드가 포함된 문서가 자동 탐색되어 에이전트 컨텍스트로 제공됩니다.

## 세부 지침

1. **단일 주제 마크다운 파일**: 
   - 하나의 파일에는 하나의 특정 주제에 대한 지식만 명료하게 기술합니다. (예: `Google_Blogger_API_사용법.md`, `Kubernetes_Operator_패턴.md`)
   - 파일 이름은 띄어쓰기 대신 언더바(`_`) 또는 대시(`-`)를 사용합니다.

2. **문서 간 위키 링크 (Linking)**:
   - 관련 문서들은 마크다운 링크 형식을 사용해 상호 연결합니다.
   - 예: `[Blogger API 문서](Google_Blogger_API_사용법.md)`
   - 위키의 최상위 대문인 [README.md](../../../wiki/README.md)에 전체 카테고리와 주요 문서 목록을 구조적으로 기술합니다.

3. **자동 RAG 작동 원리**:
   - 에이전트가 호출되기 전, 사용자의 최근 질문 텍스트에 포함된 단어(예: "Blogger", "Kubernetes")를 분석하여 `wiki/` 디렉토리 내의 관련 마크다운 문서를 검색해 자동으로 컨텍스트에 포함시킵니다.
   - 관련 내용이 없을 경우 [README.md](../../../wiki/README.md)를 기본 제공하여 지식의 전반적인 맥락을 에이전트에게 인지시킵니다.

4. **지식의 갱신 타이밍**:
   - 에이전트는 새로운 중요한 사실을 알게 되었거나 해결법을 찾았을 때, 혹은 개발 가이드라인이 수정되었을 때 주저 없이 `wiki/` 폴더 내의 지식 문서를 추가 또는 업데이트해야 합니다.

5. **종료 시 세션 자동 요약 및 기록**:
   - 에이전트 세션 종료(`Stop` 라이프사이클 이벤트) 시, 전역 훅(`stop_handler.js`)이 자동으로 가동되어 현재 세션에서 다룬 요청 및 수행된 이력을 요약합니다.
   - 이 요약본은 위키 하위의 [Session_History.md](../../../wiki/Session_History.md) 상단에 자동으로 추가되어 누적 관리됩니다.
