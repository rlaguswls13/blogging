# 대규모 로드 밸런싱 및 L4/L7 스위치

대규모 시스템에서 고가용성(High Availability)과 수평 확장성(Scale-out)을 제공하기 위한 로드 밸런싱(Load Balancing) 인프라 아키텍처 및 L4/L7 스위치의 기술 명세입니다.

## 1. 로드 밸런서의 핵심 역할

- **부하 분산**: 특정 서버 노드에 부하가 집중되지 않도록 유저의 트래픽 패킷을 다수의 백엔드 서버 그룹(Server Pool)에 공평하게 분산 처리합니다.
- **장애 극복 (Failover)**: 실시간 헬스 체크(Health Check) 메커니즘을 통해 오작동하는 백엔드 서버를 실시간 감지하여 라우팅 대상 풀에서 즉시 격리시킴으로써 무중단 서비스 제공을 돕습니다.

## 2. 네트워크 계층별 부하 분산: L4 vs L7 스위치

| 구분 | L4 스위치 (Transport Layer) | L7 스위치 (Application Layer) |
|---|---|---|
| 주요 처리 계층 | Layer 4 (TCP / UDP) | Layer 7 (HTTP / HTTPS / gRPC 등) |
| 판단 기준 | IP 주소, Port 번호, MAC 주소 | URL Path, HTTP Header, Cookie, Payload |
| 패킷 검사 깊이 | 패킷 헤더 (Header Only) | 애플리케이션 페이로드 (Deep Packet Inspection) |
| 처리 속도 및 오버헤드 | 초고속, 저지연, 낮은 CPU 부하 | 상대적으로 느림, 높음 (Full Proxy & TLS 복호화) |
| 대표적 트래픽 모드 | NAT, DSR (Direct Server Return) | Full Proxy Mode |

- **L4 로드 밸런서**: TCP/UDP 포트 번호와 IP 헤더 정보만 판별하므로 암호화된 트래픽의 복호화 과정이 불필요하며 극도의 초고속 포워딩이 가능합니다.
- **L7 로드 밸런서**: HTTP 요청 URL 경로, 헤더 필드, 쿠키를 열어볼 수 있으며 클라이언트와의 연결을 중간에 끊어 중계하는 Full Proxy 모드로 동작합니다. 지능적 라우팅이 가능합니다.

## 3. 핵심 분산 알고리즘

- **정적(Static) 방식**: 라운드 로빈(Round Robin)과 서버 성능 스펙별 가중치를 할당하는 Weighted Round Robin, IP 해싱 등이 주로 사용됩니다.
- **동적(Dynamic) 방식**: 활성 연결 수가 가장 적은 노드에 요청을 할당하는 Least Connection과 해시 링 구조를 적용하여 백엔드 서버의 증설/이탈 시 키 재배치를 최소화하는 일관성 해싱(Consistent Hashing) 등이 있습니다.

## 4. 실무 아키텍처 적용 전략

- **SSL/TLS 종단 (SSL Termination)**: L7 로드 밸런서 단에서 HTTPS 복호화 연산을 완수하여 백엔드 웹 어플리케이션의 계산 오버헤드를 현저히 낮춥니다.
- **세션 고정 (Sticky Session)**: 클라이언트 세션의 정합성 유지를 위해 쿠키/쿠키 세션 헤더 등을 해석하여 최초 접속한 서버 노드로 연속 라우팅합니다.
- **Direct Server Return (DSR)**: 로드 밸런서의 응답 대역폭 병목을 완화하기 위해 인입 요청은 로드 밸런서를 거치되, 응답 패킷은 백엔드 서버가 로드 밸런서를 거치지 않고 직접 클라이언트로 발송하는 L4 전용 아키텍처입니다.

## 5. 대표적 인프라 솔루션 예시

- **AWS Load Balancers**: L4 계층의 고정 IP 제공 및 저지연 TCP 패킷 배포는 NLB(Network Load Balancer)가 담당하고, L7 계층의 세분화된 HTTP 경로 라우팅은 ALB(Application Load Balancer)가 전담합니다.
- **오픈소스 솔루션**: NGINX는 훌륭한 L7 웹 프록시 및 캐싱 성능을 자랑하며, HAProxy는 L4/L7 영역 전반의 강력한 대규모 연결 제어 기능 및 세밀한 헬스체크 능력을 제공합니다.
